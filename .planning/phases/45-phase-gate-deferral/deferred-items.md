# Deferred Items — Phase 45

- [DEFERRED] `cmdVerifyPlanStructure`'s task-tag parser (`get-shit-done/bin/gsd-tools.js`, `taskTagPattern = /<task([^>]*)>/g`) accidentally matches the outer `<tasks>` wrapper's opening tag itself (since the string "tasks" starts with "task" and `[^>]*` swallows the trailing "s"). When a plan wraps 2+ tasks in `<tasks>...</tasks>` (rather than leaving tasks as direct top-level siblings, which is the convention used by all pre-45-02 tests), this shifts the `taskOpenTags` index-to-task attribution by one, causing a real `<task type="checkpoint:ui-qa">` task's attributes to be read from the *previous* task's opening tag instead — misclassifying it as non-checkpoint and wrongly reporting `missing <action>`. Found during task 45-02 (writing a `<tasks>`-wrapped regression test with 2 tasks including a checkpoint). Worked around in the test by omitting the `<tasks>` wrapper (matching existing convention); the underlying regex off-by-one in `cmdVerifyPlanStructure` itself was not touched — out of scope for 45-02 (unrelated to the UI_FILE_PATTERNS/computeHasUI change this plan makes).
- [DEFERRED] `gsd-tools.js state advance-plan`/`state update-progress` expect STATE.md fields formatted as `Current Plan:`/`Total Plans in Phase:` and a bolded `**Progress:**` line, but this project's actual `.planning/STATE.md` uses a different pre-existing format (`Plan: N of M in current phase`, unbolded `Progress:`). Both commands returned parse errors when run during 45-03's state-update step. Found during task 45-03 (state_updates step). Pre-existing format drift unrelated to this plan's DEFERRED.json/deferred-add-list changes — worked around by updating STATE.md's Current Position/Progress fields by hand for this plan instead of fixing the parser or the STATE.md format; out of scope for 45-03.
- [DEFERRED] Recurrence during 45-05's state_updates step: `state advance-plan` and `state update-progress` still fail to parse this project's STATE.md (same format drift as above); `state record-session` also failed (`No session fields found in STATE.md` — this STATE.md's "Session Continuity" section uses `Last session:`/`Stopped at:`/`Resume file:` unbolded labels, not whatever bolded-field pattern `cmdStateRecordSession` expects). Worked around identically: updated Current Position, Progress, and Session Continuity sections by hand. This is now a confirmed recurring gap across 45-03/45-05 (and likely every plan in this phase) — a future phase should either reformat STATE.md to match gsd-tools.js's expected schema, or update the state command parsers to match this project's actual established STATE.md conventions. Out of scope for 45-05 (a test-only plan).
