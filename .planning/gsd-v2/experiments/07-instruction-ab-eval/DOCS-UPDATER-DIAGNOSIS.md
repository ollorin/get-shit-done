# docs-updater: why B lost the wave-1 A/B, and the B2 draft

Inputs: 9 Opus judge packets and verdicts (`~/ab-eval/judge/DU*/o{1,2}/out-opus.json`, keys in `key.json`), the 18 final run reports and diffs in the packets (`sandbox/{X,Y}/{report.md,diff.patch,gates.md}`), the sub-agent transcripts under `~/ab-eval/runs/DU3-*`, `RESULTS-wave1-rerun.md`, `VARIANT-B-WAVE1.md`. A = `agents/gsd-docs-updater.md` (17,187 B, cited as A:n). B = `agents/v2/gsd2-docs-updater.md` (4,798 B on disk; the wave-1 table says 4,893; cited as B:n). B2 = `agents/v2/gsd2-docs-updater.b2.md` (7,043 B, 41% of A, +2,245 B over B). B2 has not been run; every causal claim below is a trace from judge text and run artifacts to instruction lines, not a measured effect.

## Findings in one paragraph

Three B changes explain most of the losses. (1) B generalized A's narrow "append a Phase additions section" rule into a blanket one (B:21 vs A:202, A:245), and dropped A's "wrong docs are worse than no docs" (A:33); B wrote an `### Phase ... additions` heading in 8 of 9 runs, A in 0 of 9, and B left stale text in place and appended contradicting notes (DU2). (2) B shrank the report contract to a bare template (A:343-352 field definitions gone), so B put notes in `errors` and prose in `written_files`, and B made the "empty write" case unconditionally invalid (B:60 vs A:354), so it has no legitimate way to write nothing (DU3). (3) `omitClaudeMd: true` removed the inherited CLAUDE.md rule "path-trace every claim and cite `file:line`", and B states nothing in its place, so B cites paths without the `apps/api/` prefix and its reports contradict its diffs.

## DU3: what makes A stop when nothing needs documenting

Evidence: A wrote nothing in r1 (candidate table, `written_files: []`), a CHANGELOG line in r2, and CHANGELOG plus a one-token fix in r3. B wrote `rollback.md`, `games.md`, `games.md`. A stops in 1 of 3 and no A line orders it to stop. The A text that leaves room for it:

- A:354: `[]`+`[]` is "ONLY a legitimate report for the genuine `refactoring`-with-truly-no-artifact case", and A:130 "If you cannot identify at least one concrete artifact ... write only a CHANGELOG entry, not a full doc page". A:354 then contradicts itself ("should never actually produce" it; add an explanatory `errors` entry). It is the only place an empty result is called legitimate.
- A:33 "Wrong docs are worse than no docs" and A:12 "determine documentation scope" frame skipping as acceptable. Whether these caused r1's stop is unverified: the sub-agent transcript has no thinking text. A probe that would settle it: run DU3-A with A:33 and A:354 deleted, 3 reps.

B kept A:130 as B:43, turned A:354 into an unconditional ban (B:60) and removed A:33. Under B the only compliant "nothing needed" report is `errors: [reason]`, which callers treat as a hard failure (`gsd-executor.md:278`), so B has no clean way to write nothing. B:21 also gives a general "append to any existing doc" affordance (C1). Sub-agent trace of DU3-B-r1 (`agent-ac91fd88078ffe96c.jsonl`): after every candidate named in the brief is already covered, it greps `docs/deployment/rollback.md`, finds a "400-30 precedent" and edits it. B2 step 3 and B2:67 address both.

Caveat: A's own r1 report breaks A's contract (`errors: []` with a `reason:` line), and executor `gsd-executor.md:278` fails `[]`+`[]`. The harness (`ba8fb1e`) accepts it, production does not.

## Open issues and risks

1. Contract conflict. The nothing-needed report (`[]`, `no-changes`, `[]`, plus `reason:`) is read as failure by `gsd-executor.md:278` and by `documentation_hard_gate`. DU3 can only pass in the harness. Shipping B2 requires the executor and gate to accept `commit: "no-changes"` with a `reason:` line, or a decision that DU3's "empty" ideal is wrong (the production contract demands a write). That is outside the wave-1 draft set; a CEO/Opus ruling should pick one.
2. Architecture-scope ADR entries (`docs/architecture/decisions.md`) were added by both arms in DU2 and drew "unrequested" scope penalties for A (r1, r3) and B (r2, r3). The classifier (A:66, B:31 "migration") triggers it. B2 does not change it; step 3 may reduce it. Not traced to a removed A line.
3. Frontmatter `updated` bump on edit (DU2-r2 conventions): A bumped it by chance, B2 does not instruct it.
4. Statistics: 9 pairs, 3 reps, one judge family. C1 is the best supported (9 of 9 B runs carry the heading, 8 with the exact template string); C6 and the cite rule are single-pair.
5. B2 is 7,043 B against the 6,000 B target in 07A; if the budget is firm, the cheapest cuts are the `api_change` response-table clause and the nothing-needed table (about 400 B), at some risk to C3/C4.
6. Rerun plan (not done here): `variant-from-drafts --suffix .b2` and DU1-DU3 x3, compare against A on the same G5 rule; B2 must also leave H1/G2 and DU1/DU2 acceptance unchanged.
