When the owner asks to "harden" PRDs, the pass has two halves: (1) verification — trace every claim
against current code, correct stale/absorbed scope; (2) improvement — expand around the owner's
original core ideas with high-skill, "mind-blowing", competitor-beating killer features (research
competitors, raise ambition), keeping the owner's intent as the spine rather than replacing it.
Stated 2026-09-24 when a verification-only pass was proposed.

**Why:** the PRD backlog is the product vision that must beat competitors after the PVP-first
launch ([[project_pvp_first_launch_strategy]]); a pure staleness audit leaves the ideas un-elevated.

**How to apply:** Opus runs PRD hardening (high-stakes planning per
[[feedback_use_fable_for_game_ui]]); each pass reports what was verified/corrected AND what
killer features were added, and keeps launch-gate/compliance constraints intact.
