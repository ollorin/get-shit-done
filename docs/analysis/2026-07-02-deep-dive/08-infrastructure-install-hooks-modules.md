## Install Flow — End-to-End

### Entry Points

**1. npm (direct clone)**
```bash
npm run install:gsd
```
→ `scripts/install-orchestrator.js:131` → 7-step installation

**2. npx from npm package registry**
```bash
npx get-shit-done-cc [--global|--local] [--claude|--opencode|--gemini] [--all]
```
→ `bin/install.js` (package.json bin entry) → interactive or direct install

**3. npx from GitHub fork**
```bash
npx github:user/get-shit-done
```
→ Detected by install-orchestrator.js:24–26 (temp npm cache path) → delegates to bin/install.js

### Installation Phases (orchestrated by install-orchestrator.js)

| Step | Script | Purpose | Idempotency |
|------|--------|---------|-------------|
| 1 | install-modules.js | npm install (root + workspaces + mcp-servers) | ✓ Re-runs OK |
| 2 | bin/install.js --global --claude | Copy files to ~/.claude/; register hooks in settings.json | ✓ Cleans orphans; overwrites stale files |
| 3 | install-whisper.js | Download whisper base.en model (~141MB) | ✓ Checks file size; skips if exists |
| 4 | install-hooks.js | (Legacy; now handled by step 2) | Skipped (install.js does this) |
| 5 | install-mcp.js | Register Telegram MCP in ~/.claude.json | ✓ Skips if already registered |
| 6 | generate-env-template.js | Generate .env.template | ✓ Skips if .env exists |
| 7 | health-check.js | Validate all components installed correctly | ⚠ Fails fast; doesn't skip failures |

### Detailed Flow in install.js (bin/install.js)

**Three scenarios:**

#### Scenario A: Interactive (no flags)
```
1. Prompt: Which runtime? (Claude/OpenCode/Gemini/All)     [install.js:1731]
2. Prompt: Global or Local?                                [install.js:1772]
3. Prompt: Install statusline? (if one exists)            [install.js:1680]
4. For each runtime:
   - install(isGlobal, runtime)                          [install.js:1335]
   - finishInstall()                                      [install.js:1646]
```

#### Scenario B: Explicit flags (--claude --global)
```
1. Parse args: hasGlobal, hasClaude, etc.                [install.js:20–40]
2. Skip prompts → installAllRuntimes(runtimes, true, false)  [install.js:1876]
```

#### Scenario C: Uninstall (--uninstall --global --claude)
```
1. uninstall(isGlobal, runtime)                          [install.js:780]
2. Removes: commands/gsd/, get-shit-done/, agents/gsd-*.md, hooks, settings entries  [install.js:806–986]
```

### install() Function Core (install.js:1335–1641)

**Key responsibilities:**

1. **Paths & Prefixes** (1336–1356)
   - Determine target dir: global → ~/.claude, ~/.opencode, ~/.gemini; local → ./.claude, ./.opencode, ./.gemini
   - Set pathPrefix for file references (e.g., ~/.claude/ or ./claude/)

2. **Save Local Patches** (1367)
   - If updating: backs up user-modified GSD files to gsd-local-patches/ (detected via SHA256 manifest)

3. **Cleanup Orphans** (1370)
   - Remove stale hook registrations (session-end.js, gsd-intel-*.js, etc.)
   - Update statusLine.command path if it points to old statusline.js → gsd-statusline.js

4. **Copy Commands** (1374–1401)
   - OpenCode: flatten commands/gsd/*.md → command/gsd-*.md (invoked as /gsd-help, /gsd-plan-phase, etc.)
   - Claude/Gemini: nested commands/gsd/ → commands/gsd/

5. **Copy Skill + Hook Dependencies** (1403–1422)
   - Copy get-shit-done/ with path replacement (~/. claude → target dir or ./. claude)
   - Install hook dependencies: markdown-it, gray-matter, minimatch, better-sqlite3, sqlite-vec, @xenova/transformers
   - Fails gracefully if npm install fails (compression just disabled)

6. **Copy Agents** (1424–1462)
   - Copy agents/gsd-*.md with path replacement & format conversion
   - OpenCode: convertClaudeToOpencodeFrontmatter (maps tools: → tools object)
   - Gemini: convertClaudeToGeminiAgent (strips color, converts tools array, removes <sub> tags)

7. **Copy Hooks** (1485–1503)
   - Copy from hooks/dist/ (bundled; created by build-hooks.js prepublishOnly)

8. **Configure Hooks in settings.json** (1510–1627)
   - Statusline: buildHookCommand() → node ~/.claude/hooks/gsd-statusline.js (or relative path if local)
   - SessionStart: update check hook (gsd-check-update.js)
   - PreToolUse:Read: doc compression hook (dynamic path)
   - Stop: session extraction hook (session-end-standalone.js)
   - PreToolUse:Write + Edit: managed file protection hooks

9. **Write Manifest** (1634)
   - Record SHA256 hashes of all installed files → gsd-file-manifest.json (for future patch detection)

10. **Report Local Patches** (1637)
    - Notify user if modifications found; prompt to /gsd:reapply-patches

**Return value:** { settingsPath, settings, statuslineCommand, runtime }

### finishInstall() (install.js:1646)

1. Apply statusline config to settings (if not OpenCode, not already configured)
2. Write settings.json
3. Configure OpenCode permissions (if OpenCode) via ~/.config/opencode/opencode.json
4. Print completion message with /gsd:help command

## Issues Found

### High Severity

**1. Missing hooks/dist/ on install from source**  
**File:** install.js:1486, build-hooks.js  
**Issue:** install.js expects hooks/dist/ to exist (line 1486), but build-hooks.js is only run via `npm run build:hooks` (prepublishOnly). Direct clone users running `npm run install:gsd` WITHOUT first running npm build will get empty hooks/.  
**Evidence:**  
```javascript
// install.js:1486
if (fs.existsSync(hooksSrc)) {  // hooksSrc = hooks/dist/
  const hookEntries = fs.readdirSync(hooksSrc);
```
If hooks/dist missing → verifyInstalled(hooksDest, 'hooks') fails → install.js:1505 errors with "Installation incomplete! Failed: hooks"  
**Impact:** Installation fails; users cannot proceed.  
**Fix:** Either (a) run build-hooks.js in install-orchestrator before step 2, or (b) copy from hooks/ directly instead of dist/.

---

**2. PreToolUse hooks can crash and block all Read/Write/Edit**  
**File:** install.js:1557–1626  
**Issue:** Three critical hooks registered on PreToolUse events (doc-compression, protect-managed-files). If any crashes, Claude Code stops executing that tool entirely. No error handling wrapper; no fallback.  
**Evidence:**
```javascript
// install.js:1572–1576
settings.hooks.PreToolUse.push({
  matcher: 'Read',
  hooks: [{ type: 'command', command: compressionHookCommand }]
});
```
If doc-compression-hook.js crashes → Read blocked for entire session.  
**Impact:** Session becomes unusable; user must restart Claude Code.  
**Current mitigation:** compression-hook has circuit breaker + fallback (line 5 of hook-config.json), but only AFTER hook loads.  
**Fix:** Wrap hook commands with timeout + error handler; fall back to pass-through if timeout/error.

---

**3. Orphaned Session-End SIGTERM Hook**  
**File:** install.js:726, get-shit-done/bin/hooks/session-end.js  
**Issue:** session-end.js was designed to handle SIGTERM for session extraction, but Claude Code never fires SIGTERM (verified in code comment). Hook is dead code; replaced by session-end-standalone.js which fires on Stop event. Orphan cleanup only removes from settings.json, not the file itself.  
**Evidence:**
```javascript
// install.js:726
'session-end.js',  // Removed in v1.11.0 (SIGTERM never fired — replaced by session-end-standalone.js)
```
But file still exists at get-shit-done/bin/hooks/session-end.js (3.5K).  
**Impact:** Disk clutter; if user updates from old version, orphan stays unless uninstall is run.  
**Fix:** Delete session-end.js from repo during next cleanup phase.

---

**4. No validation of file ownership/permissions on global install**  
**File:** install.js:1342–1344  
**Issue:** No check that ~/.claude is writable before copying files. If user's ~/.claude is owned by different UID or has restrictive permissions, install silently fails with "directory is empty" error (line 1139).  
**Evidence:** verifyInstalled() only checks `fs.existsSync() && entries.length > 0`; doesn't check write perms or copy success.  
**Impact:** Users get cryptic "Failed to install X: directory is empty" instead of "Permission denied".  
**Fix:** Test write permission with fs.writeFileSync() before starting install.

**9. No timeout on hook execution**  
**File:** install.js:1547–1598  
**Issue:** Hooks registered with no timeout. If doc-compression-hook hangs (e.g., database deadlock in compression-cache.js), Read tool waits forever.  
**Evidence:** Settings registration uses `type: 'command', command: ...` with no timeout field.  
**Impact:** Users can deadlock sessions; no recovery except restart.  
**Fix:** Add timeout wrapper to hook commands (e.g., `timeout 5s node ...`).

**10. Compression hook dependencies not validated until runtime**  
**File:** install.js:1416–1421  
**Issue:** installHookDependencies() fails gracefully (returns false), but install continues and registers the hook anyway. When user later triggers Read, hook loads and fails because markdown-it, gray-matter, etc. are missing.  
**Evidence:**
```javascript
// install.js:1416–1421
const depsOk = installHookDependencies(skillDest);
if (depsOk) {
  console.log(`  ${green}✓${reset} Installed hook dependencies...`);

  console.log(`  ${yellow}⚠${reset} Hook dependencies install failed — doc compression will be unavailable`);
  // But hook IS registered! It just won't work.
}
```
Hook is registered at line 1572 regardless of depsOk.  
**Impact:** User gets confusing runtime errors instead of install-time error.  
**Fix:** Don't register compression hook if installHookDependencies() returns false.

**11. Attribution processing happens before runtime-specific conversions**  
**File:** install.js:676–680  
**Issue:** For OpenCode install, processAttribution() is called BEFORE convertClaudeToOpencodeFrontmatter(). If Co-Authored-By line is in frontmatter, it might not be correctly stripped because frontmatter parsing is done afterward.  
**Evidence:**
```javascript
// install.js:676–680
content = processAttribution(content, getCommitAttribution(runtime));  // Line 676
if (isOpencode) {
  content = convertClaudeToOpencodeFrontmatter(content);  // Line 680
}
```
processAttribution() uses regex `/Co-Authored-By:.*$/gim`, but if frontmatter is malformed, regex might not match correctly before YAML parsing.  
**Impact:** Attribution not removed correctly in OpenCode installs; artifact metadata leaks.  
**Fix:** Move processAttribution() AFTER format conversion.

## Open Questions

1. **Module Workspace Structure**  
   Should placeholder modules in /modules/ have their own package.json / index.js? Currently empty stubs. Are they placeholders for future npm publish (e.g., @gsd/validator as separate package), or internal-only?

2. **OpenCode Path Handling**  
   When installing OpenCode globally, what is correct path prefix? Currently uses ~/.config/opencode/ but convertClaudeToOpencodeFrontmatter replaces ~/.claude with ~/.config/opencode. Should this be relative to ~/.config/opencode or ~/.config/opencode/get-shit-done?

3. **Gemini CLI Format Conversion**  
   Gemini agents are converted to .md files with tools array, but commands are converted to .toml. Why different? Are .md agents actually supported in Gemini CLI, or should all be .toml?

4. **Hook Registration in settings.json**  
   Should hooks be registered in a single atomic write, or is per-hook write OK? Current code does single write (finishInstall line 1658), which is good, but intermediate states could be inconsistent if process crashes mid-install.

5. **Compression Hook Graceful Degradation**  
   Circuit breaker in hook-config.json has failure_threshold: 3. What happens after 3 failures? Does hook go to "open" state and fail-fast, or does it reset? Current behavior unclear.

6. **Gemini vs Claude Hook System Parity**

- **Moderate:** Dead code (install-hooks.js, session-end.js); module confusion; orphan cleanup incomplete
- **Polish:** Attribution order, health-check messaging, module documentation
